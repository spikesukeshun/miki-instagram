# リール動画は「手動投稿」（2026-08-06〜）

## なぜ自動投稿しないか

**Instagram Graph API では本体の音源ライブラリ（トレンド音源・ライセンス楽曲）を
リールに付けられない。** REELS コンテナに音源指定のパラメータが存在せず、楽曲の
ライセンス上アプリ内操作でしか使えないため回避できない。投稿後にアプリで音源を足すことも
できない（投稿済みリールで編集できるのはキャプション・タグのみ）。

そのため **リールだけは自動投稿せず、MIKIさんがInstagramアプリから音源を選んで投稿する**。
カルーセルの自動投稿フローは従来どおり変更なし。

## 配信手順

```bash
python3 deliver_reel.py --datetime "2026/08/21 21:00" \
                        --video ~/Desktop/美喜のinstagram/miki-profile-reel/reel_new.mp4 \
                        --content-file content_2026-08-21-2100.json
```

- 事前にシートへ投稿枠の行があること（A列の日時が完全一致する行を探す）
- 動画とサムネイルを **GitHub Pages（`docs/{slug}/`）** にアップし、MIKIさんのLINEへ3通送る
  （動画 / 手順 / キャプション単独）
- **代替テキストは送らない。** リールでは入力欄が出ないことが多く、このプロジェクトでも
  `alt_text` をAPIに渡していない（`review_post.py` が形式を検査するだけ）
- キャプションを単独メッセージにするのは、LINEの長押しコピーがメッセージ単位のため
- 送信後、シートのステータスを **「手動投稿待ち」** にする

デバッグ用オプション:
- `--dry-run` … 文面とサムネイルだけ確認
- `--to-shunsuke-only` … 自分のLINEにだけ送って実機確認

## ステータスの意味

```
確認待ち →（deliver_reel.py）→ 手動投稿待ち →（Graph APIで検知）→ 投稿済み
```

- 「手動投稿待ち」は `post_scheduler.py` の自動投稿対象外
  （承認済み / 未投稿 / エラー 以外はスキップされる）
- `check_week_slots.py` からは枠が埋まっている扱いになるので、重複してカルーセルが
  作られることはない
- `post_scheduler.py` の `verify_manual_reels()` が定時実行のたびに Graph API を見て、
  枠の前後（1時間前〜72時間後）に公開されたリールがあれば「投稿済み」にして
  F列に permalink を記録する
- 24時間たっても見つからない場合は「手動投稿待ち・督促済」にしてリマインドLINEを1回だけ送る

## 配信URLに GitHub Pages を使う理由

`raw.githubusercontent` は mp4 を `application/octet-stream` で返すため、LINEが動画として
取得できない。GitHub Pages は拡張子どおり `video/mp4` を返す（実測確認済み・公開までの
ビルド待ちは約20〜40秒）。配信した mp4 は投稿確認時に `docs/{slug}/` から自動削除される。
