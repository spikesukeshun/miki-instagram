# リールの設計図を作る（フェーズ2）

リールは「写真を動かす」ものではなく、**素材の段階から動画として設計する**。
このシステムの中心は、テーマから「どの映像を何秒見せるか」を決める設計図（`plan.json`）。
動画の組み立て・音声・カバー画像・配信（フェーズ3以降）はまだ無い。

- 設計図の形と、ルールの数値の正 → `reels/plan_schema.py`（ここに数値を書き写さない）
- 検査の中身 → `reels/plan_validate.py`
- 素材の探し方 → `reels/asset_search.py`

## 流れ

```
テーマ → リール企画 → Hook → 台本 → カット構成 → 必要素材
      → 既存素材の検索 → 不足素材の特定 → 撮影依頼
```

```bash
# 1. 雛形を作る（台帳にある素材の傾向も表示される）
python3 -m reels.plan new "背中が自分では見えないからこそケアが大切" --slug back-care

# 2. Claude Code が plan.json を書く（下の「設計のルール」に沿って）

# 3. 検査＋素材探索＋不足素材＋撮影依頼 → design.md / shooting_request.txt
python3 -m reels.plan check reels/work/plans/back-care/plan.json
```

- ❌ は直すまで先に進まない。⚠️ は確認警告なので、人が見て良ければそのままでよい
- 撮影依頼の文面に出るのは**実写動画の不足だけ**。写真の不足は「不足素材」に出るので、
  Drive の写真を探すか、必要なら人が撮影依頼に足す
- `design.md` を人が読んで企画を承認する
- 撮影依頼の文面はまだ**送らない**（MIKIさんへの送信は人の確認を経てから）

## 書く順番

1. **目的**（`purpose`）：誰に、何を残し、何をしてほしいか
2. **尺**（`duration`）：短い／標準／長い から企画に合わせて選び、理由を書く。固定しない
3. **Hook**（`hook`）：冒頭に何を見せて指を止めるか
4. **台本**（`script`）：Hook／問題提起／本題／補足・具体例／CTA。全部入れなくてよい
5. **カット構成**（`cuts`）：時間軸つきで、カットごとに下の項目を全部書く
6. **ボイス台本**（`voice_script`）：ナレーションを入れる場合だけ。読みにくい言葉は `reading` を付ける
7. **CTA**・**カバー案**・**作る前に確認すること**（`open_questions`）

## カットごとに決めること

| 項目 | キー | 書き方 |
|---|---|---|
| 何を伝えるカットか | `purpose` | このカットが無いと何が伝わらないか |
| 何秒程度か | `start` / `end` | カットはすき間なく続ける |
| 何を映すか | `visual.shows` | 「背中のオイル施術を手元のアップで」のように具体的に |
| 人物の動き | `visual.person_action` | 人物がいなければ「なし」 |
| カメラの動き | `visual.camera_move` | 固定・寄る・引く・パン・手持ちで追う など |
| 画面の変化の予定 | `visual.changes` | テロップの出入り・寄り始め・切り抜きの変化などを絶対時刻で |
| どの素材を使うか | `material.preferred` と `requirements` | 被写体・人物・顔・同意・必要な長さ・動きの量 |
| 素材が無ければ何に代替するか | `material.fallbacks` | 優先順位の順に並べる |
| テロップ | `caption` | 意味のまとまりごとに分ける |
| ナレーションの有無 | `narration` | 読む文はボイス台本と同じ文にする |

## 設計のルール

### 素材の優先順位

1. MIKIさん提供の実写動画（`miki_video`）
2. 既存写真＋モーション演出（`photo_motion`）
3. 無料ストック動画（`stock_video`）— **まだ導入していない**。書いてもよいが割り当てない
4. 無料AI動画（`ai_video`）— **フェーズ6の実験扱い**。第一希望にはできない

素材を使わない場面として、文字主体（`text_card`）・自前の画面収録（`screen_capture`）、
最後の手段として内容の変更（`change_cut`）がある。
**合う素材が無い時に、合わない素材を無理に割り当てない。** 代替に回すか、撮影依頼に載せる。

素材の条件（`requirements`）の書き方：
- `subjects_all`：**必ず写っていること**（例：背中のカットなら「背中」）
- `subjects_any`：どれか1つ写っていればよい
- `actions_any`：書いたら**動作も一致が必須**。「手元」が同じでも、施術と準備、オイルとシェービングは別の映像
- `framing_any`：合えば優先するだけ（必須ではない）

2026-09-17、「手元」だけが一致して、カウンセリングのカットにソルトを混ぜる準備の映像が、
シェービングのカットに背中のオイル施術が候補として入った。**カットの中心になる被写体は `subjects_all`、動作は `actions_any` で必ず縛る。**
2枚組（比較用）の写真は、`framing_any` に「2枚組」を書いたカットにしか入らない。

### 写真だけを並べる設計にしない

- 実写動画を第一希望にしたカットが1つも無い設計は ❌
- 写真のカットを続けすぎると ❌、実写がある企画で写真の割合が大きいと ⚠️
- 写真を使う時は必ず見せ方（`photo_treatment`）を決める：寄る・引く・なぞる・切り抜く・並べて比べる・組み立てる・動画へつなぐ

### Hook

このアカウントのリールの平均視聴は約3秒（2026-09-17 に Graph API の `ig_reels_avg_watch_time` で2025年以降の11本を確認。
2025-06-12 の8.4秒のリールで3.2秒、2026-07-30 の15秒のリールで2.6秒）。
**一番見せたいもの（変化・結論・一番きれいな実写）を冒頭に置く。** 前置きや挨拶から始めない。

### テンポ（3秒ルール）

「3秒経ったら必ず切る」ではなく、**3秒以上、画面に意味のある変化がない状態を避ける**。
- 変化の予定は `visual.changes` とテロップの出入りから数える
- 3秒を超えたら**確認警告**（NGではない）
- 実写動画で人物や手元に自然な動きがある場合は、3秒を超えても問題なしとして扱う
- 静止画は、ズーム・パン・切り抜きの変化・テロップの出現で変化を作る

### テロップ

- 1行の文字数は目安を超えたら警告、上限を超えたら差し戻し（値は `plan_schema.py`）
- 長い文を一度に出さず、意味のまとまりごとに分けて時間をずらす
- 表示時間は読める長さにする（短すぎると警告）
- 見た目（白文字・透過黒背景・ゴシック・中央〜やや下・安全領域）はフェーズ3の組み立てで適用する

### ナレーション

- 基本はMIKIさんのボイスメモ（`miki_voice_memo`）。合成音声（`tts`）は代替
- 1カットに収まる長さにする（長いと警告）
- 撮影素材の元の音は基本ミュートする前提で設計する

### 事実を作らない

- **回数・期間・日数・体重などの数字には出典が必要**（`facts` に claim と出典）。出典が無ければ ❌
- 出典に使えるもの：BA登録の確認済みケース／ユーザー・MIKIさんが確認した事実／過去に投稿して承認済みの内容／サロンの確定情報
- 分からないことは推測で書かず、`open_questions` に書く

### ビフォーアフター

`miki-before-after-video/`（背中の写真に「輪郭」「横顔」の説明文を付けていた）の再発防止。
- BAを見せるカットは `tags: ["before_after"]` と `ba_case_id` を必ず付ける
- 台帳の「BA登録」タブで **状態＝確認済み・書面同意＝あり** になっているケースだけ使える。
  部位・Before/After素材・実際の施術内容・使ってよい説明文・確認者が全部そろっていること
- テロップとナレーションは「使ってよい説明文」の文面以外を使わない
- 確認できない場合、そのカットは作らない（検査が ❌ を出す）

### CTA とカバー

- 最後のカットは CTA。「プロフィール」＋「リンク」の誘導を入れる（LP誘導の恒久ルール）
- カバー案はプロフィール一覧（3:4に切り取られる）でも読める短いタイトルにする
- サロン名などの絶対ルールは `CLAUDE.md` の「絶対ルール」に従う

## 素材台帳（フェーズ0・1）

- 置き場：投稿管理スプレッドシートの「リール素材台帳」「BA登録」タブ
  （サービスアカウントは新しいスプレッドシートを作れないため。投稿用の1枚目には触れない）
- 受付：Googleドライブ「instagram投稿素材 ＞ リール素材 ＞ 01_動画・写真の受付」
- **実写動画の入口は「instagram投稿素材 ＞ 動画」フォルダ**。今ある動画も、これから撮ってもらう分もここに入れる。
  受け取り方法を増やさない（Drive の実体はコピーせず、解析結果だけを手元に置く）
- 取り込み：`python3 -m reels.ingest`（長さ・向き・回転・fps・HDR・音声・動きの量・使える区間・一覧画像）
- タグ：一覧画像を見て `python3 -m reels.catalog tag` で下書き（`AI下書き`）→ 人が確認
- 同意・使用可否：人が台帳で直接選ぶ（`未確認` の素材は「確認待ちの候補」になり、自動では割り当てない）
- 撮影の仕方：`reels/shooting_guide.md`
