# 第1部: 過去の失敗と修正記録

## 【修正済み】ローカル main が origin/main から乖離し、確定済みルールが巻き戻った（2026-08-08）

**症状**（週次ルーティンが作った 8/13・8/14 の投稿で同時に発生）:
1. 8/13分の背景6枚がすべてAI生成画像になっていた
2. シートの J列（seed）・K列（alt_text）が復活していた（2026-07-11 に廃止済みのはず）
3. 8/14分の list スライドの番号付き箇条書きが左揃えでなく行ごとの中央寄せだった

**原因（2と3に共通する本体）**:
投稿を生成しているのは **ローカルの作業ディレクトリ `~/Desktop/美喜のinstagram`** だが、
このディレクトリの `main` は **2026-04-26（9ffd908）以降 origin/main と分岐したまま一度も
同期されていなかった**。5〜8月に PR で origin/main に入った修正が、実際に画像を作る
マシンには一切届いていない状態だった。届いていなかった修正の例:

- `c7748fd`（7/11）シートI列以降の廃止 → ローカルは今も `A:K` に書いていた → 症状2
- `c6d5512` listの番号を左揃えに → ローカルは行ごと中央寄せのまま → 症状3

GitHub Actions の投稿処理（post.yml → post_scheduler.py）は origin/main を使うため、
**「画像を作るコードは4月版・投稿するコードは8月版」** という食い違いが起きていた。

**原因（1）**: 背景の選定を「Driveのファイル名一覧」だけで判断し、bridal フォルダに
Instagram書き出しのグラフィックが混ざっているのを見て「安全な在庫が無い」と誤判断し、
6枚すべて `bg_strategy: "generate"` に切り替えていた。実際には透かしのない実写が多数あった。
さらに当時の CLAUDE.md に「カバーとCTAは generate のまま」という**古い記述が残っており**、
AI生成を正当化してしまった。

**修正内容**:
- `generate_carousel.py` の `generate_list_slide()` に左揃え実装を移植
- `register_post.py` / `create_post.py` を `A:H` の8列運用に戻し、行更新のたびに I列以降を自動クリア
- `create_post.py` の `resolve_backgrounds()` は、Drive指定の不備・ファイル未検出で
  **黙ってAI生成にフォールバックせず例外で停止**するようにした
- `create_post.py` の Drive再アップロードは、**新規生成した画像だけ**に限定
  （従来は Drive から転用した実写も `bg_*.jpg` という名前だけで判定して再アップしていた。
  AI生成画像がテーマフォルダに混ざると、次の投稿がそれを実写と誤認して reuse してしまう）
- `review_post.py` に「generateは理由必須」「reuse三点セット必須」チェックを追加
- `preview_drive_images.py` を追加（Drive候補をコンタクトシート化して目視確認する）
- 週次ルーティンの SKILL.md に手順6-0「コード同期チェック」を追加

**教訓**:
- **ルールを文章に書くだけでは、コードが古いと巻き戻る。** 恒久ルールは
  `review_post.py` の機械チェックか、コード側の恒久実装のどちらかに落とすこと。
- **投稿を生成するディレクトリが origin/main から遅れていないかを毎回確認すること。**
  `python3 check_repo_sync.py` で検出できる。
- 「Driveに使える写真が無い」と結論する前に、必ず実物を目視すること。

## 【修正済み】キャプションSEO導入文なし・修正依頼フレーズの未反映（2026-04-18）

**症状①**: キャプションの1行目が「MIKIです。」になっており、SEO導入文がない
**症状②**: 修正依頼で「MIKIにお任せください♪」を指定したのに「MIKIに会いに来てください」のままだった

**原因**: 修正依頼処理後に `review_post.py` による自動校閲を実施しなかったため、
キャプション1行目ルールの漏れも、修正依頼フレーズの反映漏れも検出できなかった。

**修正内容**: `review_post.py` を新規作成し、校閲ルールをコードに落とし込んだ。

**教訓**: 「11項目を確認した」という意図だけでは不十分。スクリプトで機械的にチェックすること。
修正依頼処理時は `--revision "修正依頼文"` を追加して、依頼内容が反映されているかも必ず検証する。

## 【修正済み】タイトル改行時のレイアウト崩れ（generate_carousel.py）

**症状**: 2行タイトルのスライドでゴールドの区切り線がタイトル文字に被る・本文との距離がおかしい

**原因**: `generate_text_slide()` / `generate_list_slide()` / `generate_cta_slide()` の3関数で
`title_h = 70`（固定値）でタイトル高さを計算していた。
さらに `draw_centered()` が `\n` を解釈せず1行として描画していた。

**修正内容**: `\n` で分割して実際の描画高さを計算するヘルパーを追加し、全スライド種別に適用した。

**教訓**: content.json のタイトルに `\n` を使う場合、コード側が動的高さ計算に対応している必要がある。
固定値 `title_h = 70` のような定数でタイトル高さを扱わないこと。

## 【修正済み】ドキュメントの多重管理でルールが迷子になった（2026-08-09）

**症状**: CLAUDE.md が511行に肥大し、同じチェックリストが CLAUDE.md 内に2回・SKILL.md §14 に
1回の計3か所に存在。しかもそれぞれ内容が微妙に違っていた。

**実績監査で判明したドキュメント側のズレ**（content_*.json 27件・163スライドを集計）:

| ドキュメントの記述 | 実際 |
|---|---|
| 「AIが生成するスライド 5〜8枚」 | 27/27件が6枚。`review_post.py` は6枚超で ❌ |
| 「全スライド共通で `bg_prompt` に `no people` 必須」 | スライドレベルの `bg_prompt` は163中6枚のみ。必須なのはトップレベルの `bg_prompt` |
| CTAタイトルは改行なし版 | 27/27件が改行版。`CTA_REQUIRED_TITLE_ALT` として許容済み |
| 「`generate` は表紙や印象的な場面に使う」 | 直近16件連続で generate ゼロ |
| SKILL.md「タイトルはシャドウあり」 | 全呼び出しで shadow 未指定＝なし |
| SKILL.md「区切り線から本文まで text 100px / list 70px / cta 60px」 | 実装は 70 / 50 / 50px |
| 「主要ファイル構成（予定）」の `content/` `schedule.csv` | 存在しない |
| `python instagram_api.py --test` | `argparse` も `__main__` も無く実行不能 |

**修正内容**: CLAUDE.md を索引（絶対ルール＋実行フロー＋参照先）に絞って200行以内にし、
詳細を `rules/` と SKILL.md §14 に一本化。AGENTS.md は参照だけの入口に置換した。

**教訓**:
- **同じルールを2か所に書かない。** 書いた瞬間から片方が腐り始める。
- **コードの中の数値をドキュメントに転記しない。** px 値やデフォルト値は実装が正。
  文章には「コードが自動計算する」とだけ書く。
- ルールを変える前に、直近の投稿実績を機械的に集計して実運用と突き合わせる。

# 第2部: インサイト戦略

**下記は 2026-08-03 時点のスナップショット（当時の全投稿432件）。投稿は増え続けるので数値は
必ず古くなる。** 大きな判断（テーマ配分の見直し・投稿タイプの方針転換）をする前には必ず再取得する:

```bash
python3 insight_report.py     # 全投稿を再集計して insight_report_YYYYMMDD.md を出力
```

出力された最新レポートと下表がずれていたら、**下表ではなく最新レポートを正とし、この節を更新する**。
以下は「どの指標をどう読むか」の型として残している。

**⚠ 2026-04-14版（391件）からの重要な変更**: 旧版は廃止メトリクス（`impressions` / `plays`）の
影響でリーチが取得できておらず、**いいねだけで判断していた**。リーチを含めて見ると結論が変わる。
同じ見落としを防ぐため、レポートを読むときは必ずリーチ列が0でないことを確認すること。

| テーマ | 投稿数 | 平均いいね | 平均リーチ | 平均保存 |
|---|---|---|---|---|
| ライフスタイル・自己語り | 85 | **27.3**（最高） | 116.3 | 0.8 |
| ブライダル | 44 | 18.0 | 62.7 | **1.3**（最高） |
| メニュー・サービス | 280 | 12.9（最低） | **120.1**（最高） | 0.7 |
| ご褒美エステ | 17 | 11.6 | 70.4 | 0.8 |

| タイプ | 投稿数 | 平均いいね | 平均リーチ | 平均視聴 |
|---|---|---|---|---|
| リール動画 | 68 | **18.3** | **257.8** | **1371.5** |
| カルーセル | 299 | 16.5 | 78.6 | 187.5 |
| 単体画像 | 65 | 12.4 | 125.0 | 362.1 |

## 戦略への落とし込み

- **ライフスタイル・自己語り: 月2〜3本必須**（いいね最高27.3件・メニューの2.1倍）
- **メニュー・サービスは「本数を減らす」のではなく「切り口を変える」。**
  いいねは最低だが**リーチは全テーマ中トップ（120.1）**で、届く力はある。反応が薄いのは
  中身の問題なので、保存される形式（Q&A・早見表・チェックリスト）に寄せる
- **リールを増やす価値は旧版の想定より大きい。** カルーセル比でリーチ3.3倍・視聴7.3倍。
  月1〜2本から**月2〜3本**へ引き上げを検討する
- **ブライダルは保存率が最高（1.3件）。** 保存率を立て直したい週に有効
- プライベート投稿でリーチを稼ぐ方針は維持（歴代リーチ最高は自己語り系）
