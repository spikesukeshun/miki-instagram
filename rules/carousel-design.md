# カルーセルのデザイン仕様（案A：雑誌風・明朝・余白主義 ／ 案B：全面写真）

実装は `generate_carousel.py`。**このファイルは実装のミラーであって、正は常にコード。**
数値がコードとズレていたらコードを正としてこちらを直す。

---

## 基本構成

キャンバスは **1080 × 1350（4:5）**。写真ゾーン（上）+ クリーム帯（下）の2分割。

| 種別 | 写真ゾーン | クリーム帯 |
|---|---|---|
| `cover` | 上 55%（`photo_h_ratio` default 0.55）| 下 45% |
| `text` / `list` / `price` / `cta` | 上 35%（`slide_photo_h_ratio` default 0.35）| 下 65% |

写真と帯の境界には細いゴールドの罫線（hairline）を引く。
`slide_photo_h_ratio: 0` にすると写真なしの純クリームになる。

## 案B：全面写真レイアウト（`frame` / `phrase` / `tile`）

案Aの例外ではなく、**並立する第2の型**。キャンバスは案Aと同じ 1080×1350（4:5）だが、
2分割はせず写真を全面に敷き、その上に文字を置く。

| 型 | 文字 | 用途 |
|---|---|---|
| `frame` | `note`（任意・小さめ） | パラパラ漫画の1コマ。原則は文字なし |
| `phrase` | `phrase`（必須・大きい明朝） | 1枚1文節。スワイプで文が組み上がる |
| `cta` + `layout: "photo"` | 固定文言（案Aと同じ） | 案B投稿の末尾。構成（タイトル → 罫 → 本文 → 短い罫 → subtitle＋💌）は案Aを踏襲する。**文字は subtitle も含めて白、金は罫だけ**（案Aの金色の subtitle をそのまま使うと、白文字用に敷いた帯の上ではコントラストが足りず、LPへの導線だけ読めなくなる） |

### スクリム（可読性のつくり方）

白文字にシャドウはつけない（案Aと同じ）。代わりに**文字の下だけを沈める暗いグラデーション帯**
を敷く。濃さは固定値ではなく、**文字が載る領域の明るさを実測して決める**。

- 平均ではなく上位パーセンタイルで測る。平均だと左右の暗い部分に引っ張られ、
  文字が載る明るい箇所を見落とす（白い浴槽の上で実際に起きた）
- 帯の立ち上がり（透明→最大）は**文字の上端より上で終わらせる**。
  帯の高さに対する割合で決めると、立ち上がりが文字に食い込んで上の行だけ白飛びする
- 帯の立ち上がりは smoothstep（両端で傾き0）で描く。二乗カーブだと
  「立ち上がりが終わって一定になる点」で傾きが急に0になり、そこに横線が出る
- 明るさは**二段で測る**。面全体（低いパーセンタイル）だけを見ると、
  キャンドルの炎や窓の反射のような「面積は小さいが非常に明るい点」がすり抜け、
  そこに重なった文字だけが消える。上側のパーセンタイルも見て濃い方を採る
- 明るさは**文字が実際に載る幅だけ**で測る。全幅で測ると、文字の無い左右の暗い部分に薄められる
- ほとんどの写真では読める濃さになるが、**面積がごく小さい明点**（文字の下の小さな反射など）は
  上側のパーセンタイルでも拾えないことがある。**生成した画像は必ず目視する**
- 警告が出るのは**写真が沈みすぎる**時。案Bは写真が主役なので、出たら写真か `focus_y` を変える
- 文字（phrase・note・案B版CTA）が画面に収まらない時は、`create_post.py` が**背景を落とす前に**止める

数値（目標輝度・不透明度の上下限・帯の寸法）はすべて `generate_carousel.py` の定数が正。
ここには書き写さない。

### 案Bで写真を選ぶときの注意

案Aは写真が上35〜55%に限られ、残りをクリーム帯が覆っていた。
**案Bではその緩衝が無くなる。** bridal フォルダの AMRTA 透かしのように、
案Aでは画面外に落ちていたものがそのまま出る。写真は全面表示を前提に選び直すこと。
文字を置く下部が暗い写真ほど成立しやすい。

### mosaic（9分割・積み上げ／`tile`）

画面を3×3に割り、1枚めくるごとに区画が1つ埋まる（Red Bull の投稿形式）。
区画ごとに**別の写真**と文節1つを置き、最後の区画で写真と一文がそろう。末尾は案B版CTA。

- 区画数の正は `review_post.py` の `MOSAIC_TILE_COUNT`。tile はちょうどその枚数にする
  （`create_post.py` が画像を作る前に止める）
- まだ埋まっていない区画はクリーム
- **文字サイズは全区画で統一する**（いちばん長い文節が収まる最大のサイズ）。
  区画ごとに変えると、そろった最後の1枚で字の大きさがばらつく。
  最小サイズでも収まらない文節は止まるので、文節を短く割り直す（目安は全角4文字まで）
- **文字は白＋シャドウ。案Bで影を使うのはこの型だけ**（下記「テキストにシャドウをつけない」の例外・
  2026-09-23 ユーザー指定）。区画ごとに写真の明るさがばらばらで、スクリムを区画ごとに敷くと
  そろった時に帯の濃淡が並んで見えるため
- 文節は1行（改行なし）

## パレット（コード定数）

```python
CREAM = (250, 246, 241)   # クリーム背景
INK   = (43, 37, 34)      # 墨色（タイトル・本文の主色）
GOLD  = (184, 148, 90)    # アクセント（番号・hairline・小見出し）
```

旧 PINK / DARK / ゴールド二重枠は廃止済み。復活させない。
**案B のスクリム（下記）はこれとは別物。** 旧 DARK は「クリーム帯の代わりに濃色パネルを敷く」案で、案B は写真そのものが面になり、文字の下だけを沈める。

## フォント

- **タイトル**: 明朝 `get_serif()` — 同梱 `fonts/NotoSerifJP-*.otf` → ヒラギノ明朝 → Noto Serif CJK の順に probe
- **本文・補足**: sans `get_sans()` — ヒラギノ角ゴ → Noto Sans CJK
- **list の番号（01/02/…）**: 明朝・GOLD

## 恒久ルール（戻してはいけない実装）

### 1. list の番号付き箇条書きは左揃え

番号（01/02/…）と本文の x 座標を**全項目で揃え**、ブロック全体を中央に置く。
行ごとに中央寄せすると番号の左端がガタつくため。`generate_list_slide()` に実装済み。

**「行ごとに中央寄せ」に戻さないこと。**（2026-08 に古いコードで再発した）

### 2. テキストにシャドウをつけない

タイトル・本文・リスト項目のすべてでシャドウなし。
`draw_centered()` は `shadow=` 引数を持つが、**現行コードはどの呼び出しでも渡していない**
（案Aの余白主義に合わせた意図的な設計）。

**唯一の例外は mosaic の `tile`**（上記）。例外が他の型に広がっていないかは
`check_repo_sync.py` の `check_text_shadow_only_in_tile()` が見張る。

### 3. タイトルの高さは動的計算

`\n` を含むタイトルでも `measure_lines()` / `draw_multiline_centered()` が実際の描画高さを
計算する。`title_h = 70` のような固定値でタイトル高さを扱わないこと
（固定値だった頃、2行タイトルで区切り線が文字に被る不具合が起きた）。

### 4. 余白はコードが自動計算する

区切り線から本文までの距離などの px 値は `generate_carousel.py` の中だけで管理する。
**content.json では調整しない。この文書にも数値を書き写さない**
（SKILL.md に転記された px 値が実装と乖離したまま残っていた）。

`_slide_frame()` は `content_h` を受け取り、本文が帯に収まらない場合は
**写真ゾーンを自動的に縮めて**オーバーフローを防ぐ。

### 5. 末尾2枚はデザイン変更の対象外

`slide8.jpg`（サロン情報）と `slide7.jpg`（MIKIプロフィール）は `type: "raw"` として
`generate_raw()` が素通しで処理する。コードが自動追加するので content.json に書かない。

## content.json 側で調整できること

| フィールド | 効果 |
|---|---|
| `focus_y`（0.0〜1.0 / default 0.5）| 写真クロップの縦位置。被写体が下寄りなら 0.55〜0.65、上寄りなら 0.35〜0.45 |
| `photo_h_ratio`（cover / default 0.55）| カバーの写真ゾーン高さ比率 |
| `slide_photo_h_ratio`（default 0.35）| その他スライドの写真ゾーン高さ比率。`0` で写真なし |
| `kicker`（cover / 任意）| カバー上部の小見出し。**自動で大文字化**されるので英字推奨 |
| `tag`（cover / 任意）| カバー下部の一言 |
| `footer`（list / 任意）| リスト下部の補足（ゴールドの短い罫線つき）|
| `bubble`（任意）| `assets/` 内の透過PNG。タイトル右脇に丸型バブルを合成 |

`items` は**全角20文字以内**。折り返しなしの固定幅で描画するため、超えると画像外へはみ出す
（`review_post.py` が ❌ で止める）。

その他のフィールドは [content-schema.md](content-schema.md) を参照。
